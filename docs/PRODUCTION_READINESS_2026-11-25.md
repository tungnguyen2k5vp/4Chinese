## Đo hiệu năng và UI

- Windows x64, Node 24.11.1. `npm run benchmark:bulk` dùng SQLite trong bộ nhớ với 11.870 từ, một lượt làm nóng và ba mẫu mỗi cỡ. Median cho 1/10/50/100 từ là 0,33/4,71/34,45/54,84 ms. Mẫu 100 từ phân giải 97 từ, p95 56,66 ms. Với ba mẫu, p95 gần như là mẫu chậm nhất. [Benchmark](../scripts/benchmark-bulk-phase22-suite.ts#L57).
- 50 lần `JSON.parse` của dữ liệu HSK 3.0 trên Node cho median 27,06 ms, p95 34,46 ms. Kích thước bundle và thời gian parse trên PC đo các phần chi phí riêng; cần Android cold start và frame trace để kết luận trải nghiệm trên máy thật.
- Catalogue thật trên RN Web với fixture 100 từ mỗi trang, Edge headless, khung 390 và 1280 px. Không tràn ngang hoặc lỗi JavaScript trong hai lượt. Kiểm thử so sánh xác nhận chỉ bản bỏ guard yêu cầu offset 100 trước offset 0. Native IME, cỡ chữ hệ thống, TalkBack, inset và thời gian khởi động chưa đo.

- Baseline trên working tree 1.343 test, 238 tệp Vitest. Coverage tuyến được chọn là 81,41% statements, 78,27% branches, 82,93% functions, 85,22% lines.
- Sau sửa lỗi, Vitest đạt **1.346/1.346** qua 239 tệp. Coverage là **81,42% statements, 78,27% branches, 82,95% functions, 85,23% lines**. Một lượt chạy chồng Gradle và export web bị timeout 5 giây ở bài `i18n.test.ts:96` duyệt AST toàn bộ màn hình. Log ghi nhận timeout, không có assertion sai. Lượt chạy lại trên bản sửa cuối đạt với timeout mặc định.
- Coverage chỉ ra `device-archive.ts` có 0% lines, `i18n/storage.ts` có 25% lines, `manual-sync.ts` có 63,79% branches. Nên ưu tiên fixture khôi phục ảnh và lưu lựa chọn offline trên native, tiếp theo là test đồng bộ đầu vượt giới hạn phân trang.
- `npm run lint` chạy với 0 lỗi và 7 cảnh báo đã có từ baseline. Một cảnh báo hook về cơ chế reload `refresh` và sáu cảnh báo thứ tự import test. `npm run typecheck` và `npm run content:validate` đạt. Kiểm dữ liệu là kiểm cấu trúc bộ đóng gói; báo 0 đề thi thử đầy đủ đã xác minh.
