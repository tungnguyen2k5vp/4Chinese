# 4Chinese V5.3 — Visual Gap Audit

Date: 2026-10-06  
Baseline: pre-V5.2 `artifacts/ui-audit-2026-10-06/screens/` versus post-V5.2 `screens-v5-2-verified/`, route mapping in `capture-manifest-v5.2.csv`. All 60 manifest rows have a corresponding pre-V5.2 image; the six verified V5.2 contact sheets and the original five contact sheets were opened and reviewed before implementation.

## Visual diagnosis

The two generations still read as the same app at a glance: pale gray page canvas, large dark headings, white rounded cards, royal-blue primary actions, and repeated card/list composition. V5.2 improved individual states and some component behavior, but the important destinations retain the same information hierarchy. The Home remains a blue hero followed by stacked modules; HSK/path remain progress cards; Practice/Library remain grouped rows; Reader still leads into input/tool UI; Speaking is button/form-led; Stats and Achievements emphasize zero-value metric cards; onboarding remains a tall selectable list. Illustrative identity and differentiated Learn/Review/Read/Exam moods are not yet sustained across routes.

Additional evidence/gaps visible in the baseline:

- The audit data often has no progress (0 XP, 0 learned, empty review/decks), so it cannot demonstrate the intended active learner states.
- Learning Path's current route screenshot is mostly a vertical course-card list; the course page's lesson timeline is a start but not yet a journey map.
- Speaking AI combines many scenario/level choices and conversation controls in one long setup surface instead of a clear setup → chat → result experience.
- The current dev-build screenshots show a floating development control; content-review is an internal `__DEV__` route but is present in the debug capture set.
- `mistakes_practice.png` is an intentional invalid-ID test that displays a system-looking alert; a branded in-app error state is preferable while preserving native permission dialogs.

The brief reports a rough earlier comparison of 39/60 screens under ~1% pixel change and 47/60 under ~5%; those figures are treated as an input from the brief, not re-measured in this audit. Pixel diff is a signal only; acceptance is based on changed structure, hierarchy, interaction, and recognizable 4Chinese identity.

## V5.3 acceptance gate

Tier A is not done on token/color/radius changes alone. Its after image must demonstrate a changed structure, hierarchy, interaction and identity while retaining the existing route and learning semantics. Tier B must show a meaningful task-first change. Tier C intentionally remains utility-focused. Evidence is compared at the same emulator viewport and representative data state; pixel difference is supplementary, not the verdict.

Mandatory cross-cutting checks: app-owned error presentation (not OS permission prompts), internal/QA route gating, deterministic preview-only audit data, Learn/Review/Read/Exam visual modes, dark surfaces, Vietnamese/Chinese font growth to 160–200%, TalkBack semantics where testable, reduced-motion behavior, touch targets, and no database reset/migration or change to SRS/exam/HSK logic.

## Skills and platform constraints used

Reviewed: `agency-mobile-ui-ux-engineer`, `agency-expo-react-native-engineer`, `agency-mobile-device-qa`, `agency-mobile-testing-engineer`, `agency-accessibility-auditor`, and `agency-react-native-performance-engineer`. Repo uses Expo SDK 57 / React Native 0.86 with Expo Router, Reanimated, and SVG; the exact versioned [Expo SDK v57 reference](https://docs.expo.dev/versions/v57.0.0/) was checked. Physical-device installation is explicitly out of scope for this task until the user approves it.
